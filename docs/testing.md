# Как проверяется расширение

Четыре независимых слоя. Первые два обязательны на каждый коммит, третий и
четвёртый — перед релизом и при изменении UI/логики.

| Слой | Команда | Что проверяет | Время |
| --- | --- | --- | --- |
| Юнит-тесты | `npm test` | Чистая логика: сортировка, фильтры, поиск, перестановка внутри фильтра, импорт/экспорт, миграция, состояние панели | ~1 с |
| Статика | `npm run validate` | Собранный манифест и локали: версии, иконки нужных размеров, пути из манифеста, разрешения, i18n-ключи, форма `messages.json`, гигиена кода, zip | ~1 с |
| Браузерный дым | `npm run load-test` | Расширение грузится, SW стартует, панель и popup рендерятся, локали ru/en, светлая и тёмная тема, компактный режим, пустое состояние, состояние панели после перезапуска SW, скриншоты | ~20 с |
| E2E-сценарий | `npm run e2e` | Миграция данных, добавление, отметка, черновик при внешней записи, утечка слушателей, перестановка мышью и с клавиатурой, поиск с подсветкой, фильтры, undo, подтверждение удаления, экспорт/импорт, персистентность | ~30 с |

Всё вместе: `npm run verify && npm run load-test && npm run e2e`.
Результаты — в `artifacts/`: `load-test.json|log`, `e2e.json|log`, скриншоты
`panel-ru-light.png`, `panel-ru-dark.png`, `popup-ru.png`, `e2e-final.png`.

## Chrome для тестов

С Chrome 137 branded Chrome **игнорирует `--load-extension`**, поэтому нужен
Chrome for Testing или Chromium. Порядок поиска бинаря:

1. `CHROME_BIN=/path/to/chrome`;
2. `tools/chrome-linux64/chrome` (симлинк на локальную сборку);
3. кэш Playwright (`~/.cache/ms-playwright/chromium-*`);
4. `/usr/bin/google-chrome` — с предупреждением, что может не сработать.

В контейнере нужен `--no-sandbox` (уже передаётся).

## Локаль

Язык интерфейса задаётся **окружением процесса** (`LANGUAGE`, `LANG`, `LC_ALL`),
а не флагом `--lang` и не `intl.app_locale` — так ведёт себя Chrome 158 в headless
(подробности в `docs/knowledge-base.md`, раздел 3). `npm run load-test` прогоняет
`ru` и `en`; можно ограничиться одним языком:

```bash
LOCALES=en npm run load-test
```

О локали судим по выводу `chrome.i18n.getMessage()`, а не по `getUILanguage()`.

## Как это сделано в коде

`scripts/cdp.mjs` — запуск Chrome с расширением + минимальный CDP-клиент.
Страницы расширения открываются через `Target.createTarget`, действия
эмулируются настоящими событиями (`Input.dispatchMouseEvent`,
`Input.dispatchKeyEvent`, `DOM.setFileInputFiles`). Никакого Playwright/Puppeteer:
зависимостей ноль.

Счётчик слушателей на `document` (`window.__docListeners`) ставится через
`Page.addScriptToEvaluateOnNewDocument` — так ловится регрессия «по слушателю на
рендер», которая была в 3.0.

## Ручной чек-лист перед релизом

Автотесты не покрывают user gesture и реальную панель, поэтому руками:

1. Загрузить `dist/` распакованным, открыть панель **кликом по иконке** и
   сочетанием `Ctrl+B`; проверить, что панель открывается и закрывается.
2. Открыть панель на `chrome://extensions` — должно появиться сообщение
   «На этой странице Chrome панель открыть нельзя».
3. С двумя окнами браузера: открыть панель в первом, затем во втором — popup
   должен показывать состояние **своего** окна.
4. Перезапустить браузер с открытой панелью: Chrome восстанавливает панель, popup
   должен показывать «открыта».
5. Проверить тёмную тему (системная настройка) и масштаб 150 %.
6. Экспортировать задачи, удалить все, импортировать файл обратно.
7. Обновить расширение поверх версии 3.0 с задачами — список должен перенестись
   (в уведомлении «Перенесено задач: N»).
